# 0002. Протоколы моделей пишем сами поверх reqwest

- Статус: Принято
- Дата: 2026-10-28

## Контекст

`mentor-llm` переводит запросы ядра в протокол сервиса модели. Два протокола покрывают нужные сервисы: OpenAI-совместимый (OpenAI, OpenRouter, Ollama и любой сервис с тем же API) и собственный протокол Anthropic.

От протокола требуется:

- структурированный ответ по схеме, которую выводим из типов Rust, с особенностями строгой схемы каждого сервиса;
- поток ответа (SSE), чтобы показать первый шаг плана раньше конца ответа;
- отмена запроса по его номеру;
- свои виды ошибок из статуса и тела ответа: нет доступа, кончилась квота, сервис недоступен, сервис занят, сеть, время ожидания, негодный ответ;
- никаких скрытых повторов: повтор — явное решение нашего кода;
- кэш системного текста запроса у Anthropic, учёт токенов и времени;
- контрактные тесты на записанных ответах без трат токенов в CI.

Библиотеки, проверенные на crates.io 2026-10-28: `genai` 0.7.2, `rig-core` 0.46.0-rc.1, `async-openai` 0.42.2.

## Решение

`mentor-llm` объявляет трейт протокола с нейтральными типами запроса и ответа и реализует его дважды: OpenAI-совместимый протокол и протокол Anthropic. Обе реализации написаны поверх `reqwest`, разбирают поток SSE сами и описывают сообщения каждого сервиса своими типами `serde`. Ошибки сервиса сводятся к нашим видам ошибок внутри протокола. Повторов в транспорте нет. Повтор делает только наш код по явному правилу, например один повтор с текстом ошибки при негодном структурированном ответе, затем негодный ответ.

## Рассмотренные варианты

- **`genai`.** Один API для многих сервисов. Версия 0.x, минорный выпуск может ломать API. Запрос, ответ и ошибки описаны типами библиотеки: наши виды ошибок пришлось бы восстанавливать из её типа, а особенности сервиса доступны настолько, насколько их выставила библиотека.
- **`rig-core`.** Библиотека для приложений на моделях с агентами и инструментами. Цикл агента у нас живёт в ядре (ADR [0001](0001-core-reduce.md)), второй цикл в библиотеке ему противоречит. Версия 0.x.
- **`async-openai`.** Только API OpenAI. Протокол Anthropic всё равно писать самим, и тогда два протокола устроены по-разному.

## Последствия

- Всё, что уходит в сервис и приходит из него, видно в нашем коде и проверяется тестами на записанных ответах.
- Сетевая зависимость одна: `reqwest`, только в `mentor-llm`. Поток SSE разбирает наш код, без отдельной библиотеки со своими повторами. В ядре `reqwest` запрещён проверкой `cargo xtask check`.
- Изменения API сервисов отслеживаем сами. Третий протокол означает ещё одну реализацию трейта.
