# Как вносить изменения

Как поставить зависимости и запустить приложение, описано в [README](README.md). Как устроен код, описано в [docs/architecture.md](docs/architecture.md).

## Ветки

- Одна ветка на один пулл-реквест, от свежего `main`.
- Имя ветки: `область/коротко`, например `core/text-match` или `ci/release`.
- Перед слиянием ветка перебазируется на `main` (`git rebase main`). `main` в ветку не вливается.

## Коммиты

Каждый коммит ветки попадает в `main`, поэтому каждый оформлен как законченное изменение. Черновые коммиты склеиваются через `git rebase -i` до открытия пулл-реквеста.

Заголовок коммита:

```
тип(область): описание
```

- Описание по-русски, без точки в конце, весь заголовок не длиннее 72 символов.
- Ломающее изменение отмечается `!` после области, а в теле коммита пишется `BREAKING CHANGE:` и что поменять.
- Формат проверяет `cargo xtask commits`, в пулл-реквесте его проверяет CI.

| Тип | Когда |
|---|---|
| `feat` | Новое поведение |
| `fix` | Исправление ошибки |
| `perf` | Ускорение без смены поведения |
| `refactor` | Перестройка кода без смены поведения |
| `test` | Только тесты и тестовые данные |
| `docs` | Только документация |
| `ci` | Только CI |
| `build` | Сборка, зависимости, инструменты |
| `chore` | Прочее: конфигурация, релизный коммит |
| `style` | Только форматирование |
| `revert` | Откат коммита |

| Область | Что это |
|---|---|
| `core`, `engine`, `llm`, `platform`, `storage`, `testkit` | Пакеты `mentor-*` в `crates/` |
| `app` | Приложение Tauri в `app/src-tauri` |
| `ui` | Интерфейс в `app/src` |
| `ci` | Workflow GitHub Actions |
| `repo` | Workspace, `xtask`, конфигурация репозитория |
| `release` | Версии, changelog, установщик |
| `docs` | Документация |

## Пулл-реквест

- Одна мысль на пулл-реквест: до ~400 строк без тестов, сгенерированных файлов и тестовых данных. Больше — разделить.
- Описание по шаблону: что, зачем, как проверить, скриншот для интерфейса.
- Слияние merge-коммитом, только при зелёных проверках.

Перед открытием пулл-реквеста:

```sh
cargo xtask check
cargo xtask coverage
cargo xtask commits
cd app && bun run check
```

## Тесты

- Приватная логика модуля проверяется модульными тестами в том же файле (`#[cfg(test)] mod tests`). Если тестов больше, чем кода, они выносятся в `модуль/tests.rs`.
- Всё, что проверяется через публичный API пакета, в том числе сценарии на данных из `testdata/`, лежит в `crates/<пакет>/tests/`.
- Тесты интерфейса лежат рядом с компонентом: `Component.test.ts`.
- Покрытие не ниже 80% для Rust и для интерфейса. Исключения перечислены явно в `xtask` и в `app/vite.config.ts`: только код запуска приложения.

## Код

- У публичных типов и функций есть doc-комментарии, это проверяет линт `missing_docs`.
- Комментарии объясняют код. `TODO` пишется только с номером задачи: `// TODO(#12): …`.
- `mentor-core` не зависит от асинхронной среды, сети, ОС и Tauri, это проверяет `cargo xtask check`.
- Если пулл-реквест меняет устройство кода, в нём же обновляется `docs/architecture.md`, а решение записывается в `docs/adr/` по [шаблону](docs/adr/0000-template.md).
